# 网文文风画像与一致性自检

本技能把用户授权的样本或抽象风格要求转成可执行、可校验的《风格画像》。它负责分析和约束，不替代 `webnovel-writing` 的草稿、校验、发布与回滚流程。

## 一、使用边界

在以下情况加载本技能：

- 用户提供自己的文本并要求延续风格；
- 用户提供公版、已授权或短小参考片段；
- 用户用“短句、冷峻、对话密集、规则怪谈”等抽象特征描述目标风格；
- 用户反馈“这章不像”“节奏不对”或“AI 味太重”。

不要承诺精确复制在世作者的独特风格。遇到这类要求时，把目标转换成高层特征，例如叙事距离、句长、段落密度、对话比例、信息释放、情绪强度和章末方式，并产出原创表达。不得保存或复现大段无授权原文。

## 二、收集样本

优先使用用户提供或明确授权的文本。短样本尽量覆盖开篇、对话、冲突和收束四类场景；只有一段时，应说明画像置信度有限。

对长文件先做统计抽样，不要把整本书塞进上下文。建议提取：

- 单章字数分布；
- 每章段落数；
- 段落长度均值、中位数和 P90；
- 长段落占比；
- 句长和每段句数；
- 对话字数占比、台词长度、引号开头段落占比；
- 感叹号、问号、省略号、破折号等标点频次；
- 章末最后一段的长度和结束符分布；
- 高频功能词、动作提示语和场景切换方式。

统计只能描述文本形状，不能代替精读。至少精读开篇、一次关键冲突、中段普通章和收束章，确认数字背后的叙事作用。

## 三、创建风格画像

项目存在 `风格画像.md` 时，修改前先备份。使用以下结构：

```markdown
# 《书名》风格画像

## 目标
- 来源与授权范围：
- 一句话概括：
- 适用场景：

## 硬指标
| 指标 | 样本观察 | 本作目标区间 |
|------|----------|--------------|
| 单章字数 | | |
| 每章段落数 | | |
| 段落长度（均值/中位/P90） | | |
| 对话占比与台词长度 | | |
| 关键标点频次 | | |
| 章末长度与结束方式 | | |

## 叙事规则
- 视角与叙事距离：
- 信息释放顺序：
- 场景切换方式：

## 语言规则
- 句式与段落：
- 词汇与语域：
- 描写密度：
- 对话与提示语：

## 节奏与情绪
- 冲突密度：
- 爽点、恐惧、温情或幽默的实现方式：
- 章末处理：

## 禁忌
- 不使用：
- 不超过：
- 必须避免的 AI 套话：

## 写作检查清单
- [ ] ...

## 迭代记录
- 日期：反馈、判断、修改内容
```

每条规则都必须可执行。不要只写“语言生动”“节奏紧凑”；应改成“每段一到三句”“重要设定先在行动中出现，再用一句对话确认”“高潮前连续缩短段落”等可以检查的描述。

## 四、把画像应用到章节

写作前只提取本章相关的五到十条约束，避免让过多指标压垮内容。优先级如下：

1. 用户本轮明确要求；
2. 项目已确认的风格画像；
3. 当前场景的叙事需要；
4. 通用网文建议。

写完后分两轮检查：

- 内容轮：因果、人物、设定、伏笔和场景目标；
- 风格轮：句段、对话、词汇、信息密度、情绪和章末。

不要为了命中数字破坏可读性。量化区间用于发现偏差，不是逐句机械配额。明显偏离时先定位原因：如果是高潮、书信、档案等特殊场景导致，可以记录例外；如果是无意走样，修改草稿后重新检查。

## 五、反馈闭环

用户说“不像”时，不要只换几个词：

1. 找出用户不满意的是叙事距离、节奏、对话、措辞、情绪还是结构；
2. 对比样本、画像和问题段落，指出可观察差异；
3. 备份 `风格画像.md`；
4. 把反馈改写成新的可执行规则；
5. 重写受影响草稿；已发布章节需先取得用户授权并按回滚流程处理；
6. 在迭代记录中写明反馈和调整。

用户认可某一章为新基准时，完整阅读该章及相邻章节，更新画像后再继续写，不要只凭一句“按这一章”自行猜测。

## 六、原创与引用

- 可以分析句长、节奏、视角、结构、对话密度等抽象特征。
- 不得复制大段原文、逐句改写、替换专名后复用情节，或把样本中的独特表达搬进新作。
- 画像中只保留必要的短例子和统计结果，并记录来源与授权范围。
- 用户自己的作品可以做细致延续，但仍要尊重其指定保留的原句和既有设定。
- 无法确认授权时，使用少量片段做分析，交付原创文本，不建立可传播的原文语料库。
